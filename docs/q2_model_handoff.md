# 第二问模型交接说明

## 1. 对应评分细则

第二问评分细则主要看三件事：

1. 明确给出决策依据和数量指标，例如期望成本、收益或利润。
2. 给出决策分类和对应计算模型，模型要能处理多种情形。
3. 针对零配件检测、成品检测、拆解处理进行分类讨论，并尽量简化求解过程。

本仓库采用的核心指标为：

```tex
\Pi = S - E
```

其中 \(S\) 是市场售价，\(E\) 是为了最终交付 1 件合格成品所需承担的期望成本。最终选择期望利润最大的策略。

## 2. 建模策略

第二问看似有很多决策，但可以先做局部判断来减少枚举数量。同时，拆解后的零配件要单独处理，因为“首次是否检测”和“拆解后是否检测”并不是同一个问题。

第一步，对每种零配件设置 3 种策略：

```tex
m_i\in\{0,1,2\}.
```

其中：

- \(m_i=0\)：第一次检测，拆解后不检测。因为第一次检测合格后才进入装配，拆解不会损坏零配件，所以拆解后仍视为合格件。
- \(m_i=1\)：第一次不检测，拆解后也不检测。
- \(m_i=2\)：第一次不检测，拆解后检测。

因此零配件策略共有：

```tex
3\times 3=9
```

种。

第二步，对每一种 \((m_1,m_2)\)，计算初始装配时的成品不合格概率 \(q\)。

第三步，用局部占优判断直接确定成品是否检测：

```tex
t_f<qL.
```

若成立，则检测成品；否则不检测成品。

第四步，枚举拆解决策：

```tex
z=0,1.
```

第五步，对剩下的候选策略计算总期望利润，并选择全局最优。

一句话概括：

```tex
\boxed{\text{局部判断可以减少枚举数量，但最终最优策略仍要靠总期望利润比较。}}
```

## 3. 程序对应关系

程序文件：

```text
programs/q2_decision_model.py
```

该程序对每个情况计算 18 个候选策略：

```tex
9\text{ 种零配件策略}\times 2\text{ 种拆解决策}.
```

其中成品检测 \(y\) 不再枚举，而是由

```tex
t_f<qL
```

自动判断。

## 4. 输出文件

运行程序后生成：

```text
programs/results/q2_policy_results.csv
programs/results/q2_best_policies.csv
```

`q2_policy_results.csv` 包含所有候选策略。

主要字段：

- `case`: 表 1 中的情况编号。
- `part1_mode`: 零配件 1 的三态策略。
- `part2_mode`: 零配件 2 的三态策略。
- `part1_mode_id`, `part2_mode_id`: 三态策略编号，0 表示首次检测，1 表示始终不检测，2 表示拆解后检测。
- `product_defect_prob_q`: 当前零配件检测策略下的成品不合格概率 \(q\)。
- `qL_minus_tf`: 成品检测判断指标 \(qL-t_f\)。若大于 0，则检测成品。
- `inspect_product_by_rule`: 由 \(t_f<qL\) 得到的成品检测决策。
- `disassemble`: 是否拆解不合格成品。
- `feasible`: 该策略是否有有限期望成本。若拆解后把未检测坏件反复装回去，可能出现不可行策略。
- `expected_cost`: 交付 1 件合格成品的期望成本。
- `expected_profit`: 交付 1 件合格成品的期望利润。

`q2_best_policies.csv` 只保留每种情况的最优策略。

## 5. 论文写作建议

论文手可以按下面顺序写第二问：

1. 定义零配件三态策略 \(m_1,m_2\)，以及成品检测变量 \(y\)、拆解变量 \(z\)。
2. 定义期望成本 \(E\) 和期望利润 \(\Pi\)。
3. 对 9 种零配件策略计算初始成品不合格概率 \(q\)。
4. 用 \(t_f<qL\) 判断成品是否检测。
5. 对拆解决策 \(z=0,1\) 进行枚举。
6. 用状态递推计算总期望利润。
7. 用表格展示 6 种情况的最优策略、期望成本和期望利润。

建议画图：

- 每种情况最优期望利润柱状图；
- 每种情况 18 个候选策略的期望利润对比图；
- “零配件检测 - 成品检测 - 拆解 - 利润比较”的流程图。
